## 1. 이게 뭐야?

**AI 에이전트(Claude / Codex)에게 주는 "업무 매뉴얼 세트"입니다.**

프로그램이 아니라 **글로 쓴 규칙집**입니다. 파일 비중이 이를 증명합니다.

| 종류 | 개수 | 정체 |
|---|---|---|
| `.md` 마크다운 | **174개** | 본체. AI가 읽는 지시서 |
| `.py` 파이썬 | 59개 | 검증·설치·파이프라인 도구 (보조) |
| `.json` | 47개 | 노트 형식 규칙(스키마) |

### 해결하려는 문제 3가지

1. **AI가 세션 간에 기억을 잃는다** → 옵시디언 볼트에 지식을 영구 저장
2. **AI가 증거 없이 "다 했어요"라고 주장한다** → 검증 게이트로 차단
3. **좋은 자료를 봐도 남는 게 없다** → 출처·개념·링크로 구조화해 축적

### 폴더 구조

```
skills/       ← 핵심. 21개 스킬 (각 폴더에 SKILL.md 1개)
contracts/    ← 노트가 지켜야 할 형식 계약서 (JSON 스키마 47개)
tools/        ← 실제 동작하는 파이썬 (린터, 워커 파이프라인)
commands/     ← /daily-okr 등 슬래시 명령 4개
adapters/     ← Cursor·Windsurf용 변환기
examples/     ← 3분 퀵스타트 등 사용 예제
outreach/     ← 홍보/성장 자료 (기능과 무관)
install.sh    ← 설치 스크립트
```

### 21개 스킬

**핵심 3개 (이것만 써도 본전)**

| 스킬 | 설명 |
|---|---|
| `verify-before-claim` | 완료 선언 전에 증거(테스트 결과, exit code)를 강제 요구 |
| `wiki-ingest` | PDF·URL·자막 → 출처 보존 + 개념 노트 + 링크 구조화 |
| `daily-okr` | 하루 7단계 루프(입력→사고→위키→행동→창의→산출→피드백) |

**나머지 18개**

`deep-research`, `cognitive-compile`, `knowledge-ops`, `wiki-lint`, `context-manager`,
`session-learn`, `project-flow-ops`, `behavior-design`, `creativity-engine`,
`workflow-audit`, `loop-engineering`, `graph-engineering`, `agentic-engineering`,
`harness-engineering`, `agent-teams-command`, `startup-evaluation`, `anthropic-os`,

## 2. 설치 및 사용법

### 설치

```bash
git clone https://github.com/bmshin94/third-brain-v7-skills
cd third-brain-v7-skills
bash install.sh claude
```

하는 일은 단 하나 — `skills/` 폴더 21개를 `~/.claude/skills/`로 **복사**합니다.

```bash
ls ~/.claude/skills/ | wc -l    # 21 나오면 성공
```

| 대상 | 명령 |
|---|---|
| Claude Code | `bash install.sh claude` |
| Codex (원래 주 대상) | `bash install.sh codex` |
| 전체 | `bash install.sh all` |
| Windows | `.\install.ps1 claude` |

### 사용법

명령어를 외울 필요 없이 **평소처럼 말하면** 됩니다. 각 `SKILL.md` 상단의
`description`("언제 쓰는지")을 AI가 읽고 스스로 판단해 발동합니다.

```
"이 아티클 내 위키에 정리해줘"       → wiki-ingest
"오늘 데일리 OKR 돌려줘"            → daily-okr
"다 됐다고 하기 전에 증거부터 보여줘"  → verify-before-claim
```

### 설치 후 필수 작업

`wiki-ingest` 계열은 **옵시디언 볼트 경로**를 알아야 동작합니다.
현재는 원작자 경로가 그대로 남아 있습니다.

```
D:/C-Drive-Relocated/Personal/Documents/Obsidian Vault   ← 남의 컴퓨터 경로
```

`system/config.md`를 본인 볼트에 복사해 경로를 수정해야 합니다.

## 3. 플러그인? 스킬? MCP? → **스킬입니다**

| | 정체 | 비유 | 이 저장소 |
|---|---|---|---|
| **스킬 (Skill)** | 마크다운 지시서 | AI에게 주는 업무 매뉴얼 | **해당** |
| **MCP** | 실행되는 서버 프로그램 | AI에게 달아주는 손과 발 | 아님 |
| **플러그인** | 스킬+명령어+훅 묶음 배포 형식 | 매뉴얼 패키지 상품 | 아님 |

### 스킬인 근거

```yaml
---
name: cognitive-compile
description: Use when source material must be transformed into...
---
```

Anthropic 공식 Agent Skills 표준 포맷(`name` + `description` 프론트매터)을 따릅니다.
린터 실행 결과 **21개 전부 통과**했습니다.

```
$ python3 tools/lint-agent-skills.py
Agent Skills lint passed for 21 skills.
```

### 핵심 차이

- **MCP는 "능력"을 추가** — 원래 못 하던 일을 하게 됨 (DB 조회, 슬랙 전송 등)
- **스킬은 "행동방식"을 추가** — 원래 하던 일을 더 일관되게 하게 됨

플러그인이 아닌 이유: `.claude-plugin/plugin.json` 같은 매니페스트가 없고,
단순 폴더 복사 방식입니다. `hooks/` 폴더가 있지만 README에
**"실행 가능한 훅은 하나도 없으며 설계 아이디어 문서일 뿐"** 이라고 명시돼 있습니다.

## 4. API 토큰이 필요한가? → **불필요**

코드 전체를 검사한 결과입니다.

| 검사 항목 | 결과 |
|---|---|
| API 키 요구 | 없음 |
| 외부 네트워크 호출 (`requests`, `fetch`) | **없음** |
| 의존성 파일 (`requirements.txt` 등) | 없음 = 순수 파이썬 표준 라이브러리만 |
| 데이터 외부 전송 | 없음 |

`urllib`이 있으나 **URL 문자열 파싱 용도**이지 통신용이 아닙니다.
웹 서버도 localhost 전용임이 코드 주석에 명시돼 있습니다.

> "Small, **localhost-only** host... This module **never accepts a command, path,
> shell fragment, or verifier from a browser request**."
> — `tools/agentic_os_server.py`

**완전 오프라인 · 완전 로컬 동작.**

### 단, 비용은 발생

저장소는 무료지만 **Claude 자체 사용료**는 듭니다. 스킬 파일이 프롬프트에 얹히므로
토큰을 더 소모합니다. 그래서 `context-manager`와 `token-cost-tracker`가 포함돼 있습니다.

> 참고: `SUBSTANCE.md`가 언급한 `GITHUB_TOKEN` 필요 홍보 스크립트 4개
> (`find-awesome-pr-targets.py`, `submit-awesome-prs.py`, `configure-github-repo.py`,
> `growth-loop.py`)는 **현재 모두 삭제**되었습니다. 문서가 낡은 것입니다.

저장소 안에 **실제 스타 수가 기록**돼 있었습니다.

  "metrics": { "stars": 117, "forks": 18, "watchers": 1, "open_issues": 0 },
  "star_delta_since_previous_report": 0,
  "growth_readiness_score": 80

**스타 117개.** 유명한 저장소는 보통 수천~수만입니다. 마지막 기록일 스타 증가는 **0개**였습니다.

### 그럼에도 눈에 띄는 이유 3가지

**① 문제 설정이 강력하다**
"AI가 자꾸 까먹는다", "AI가 거짓말한다" — 모든 개발자가 공감하는 고통입니다.

**② 홍보 체계가 잘 갖춰져 있다**

```
outreach/launch/
├── show-hn.md               ← 해커뉴스 초안
├── product-hunt.md          ← 프로덕트헌트 초안
├── reddit-post.md           ← 레딧 초안
├── x-thread.md              ← X 스레드 초안
└── devto-article-outline.md ← Dev.to 초안
outreach/awesome-lists/      ← awesome 리스트 등재 신청 템플릿 (후보 9개 자동 선별)
outreach/growth-reports/     ← 매일 스타 수 자동 추적 (30개 이상)
```

**③ 규모가 압도적으로 보인다**
스킬 21개 + 스키마 47개 + 파이썬 59개 + 테스트 97개 + 아키텍처 다이어그램.

### 다만 정직합니다

저장소가 `SUBSTANCE.md`에서 홍보 장치의 존재를 **스스로 공개**했습니다.

> "스타 수는 품질 신호가 아니다. 쓸모있는 저장소도 쓸모없는 저장소도 둘 다 스타를 받는다."
> "**직접 하나 써봐라. 되면 계속 쓰고, 안 되면 버려라.** 그게 필요한 검증의 전부다."

## 6. 로컬 에이전트 구축에 도움이 될까?

**설계 참고서로는 강력 추천. 그대로 갖다 쓰기에는 부족.**

### 가져올 가치가 확실한 것 3가지

**① "증거 없으면 완료 없음" 게이트** (`verify-before-claim`)

```
1. 주장을 반증 가능한 한 문장으로 다시 쓴다
2. 위험도 분류: 낮음 / 중대 / 치명적
3. 그 주장을 직접 검증하는 가장 싼 방법을 고른다
4. 마지막 수정 이후에 실행한다 (오래된 증거 금지)
```

어떤 에이전트에도 즉시 이식 가능한, 가장 값어치 있는 부분입니다.

**② 트랜잭션 파이프라인 패턴** (`tools/worker_flow/`)

```
Stage(준비) → Author(작성) → Submit(검증) → Commit(반영) → Postcheck(확인)
```

에이전트가 파일을 즉시 수정하지 않고, 임시 공간에 만든 뒤 검사·승인을 거쳐 반영합니다.
실패 시 롤백됩니다. CLI가 실제로 동작함을 확인했습니다.

```
$ python3 -m tools.worker_flow.cli --help
Third Brain V8.1 transactional Obsidian workflow
{scan,prepare,prepare-local,prepare-system,prepare-retrofit,
 stage-candidate,submit,commit,status,freshness-scan,inventory}
```

**③ 영수증(Receipt) 시스템**

모든 작업에 `run-20260820T142737Z-be706a66` 형식 ID와 JSON 영수증을 남깁니다.
재시도해도 중복 기록되지 않도록 하는 idempotency key 개념도 포함돼 있습니다.

### 기대하면 안 되는 것

| 착각 | 현실 |
|---|---|
| "강제로 막아주겠지" | 대부분 **프롬프트로 부탁**하는 수준. AI가 무시하면 그만 |
| "훅으로 자동 실행되겠지" | `hooks/README.md`에 **"실행 가능한 훅 없음"** 명시 |
| "설치하면 바로 동작하겠지" | 볼트 경로 설정 필요 |
| "21개 다 완성됐겠지" | 저작자가 *"일부는 희망사항(aspirational)"* 이라고 인정 |

### 검증 결과 (직접 실행)

| 검사 | 결과 |
|---|---|
| Agent Skills 린트 | **21개 전부 통과** |
| worker_flow CLI | **정상 동작** |
| 유닛 테스트 | **95 통과 / 2 실패 / 4 스킵** |

실패한 2건: `test_install_sh` (환경 의존), `test_repository_governance` (windsurf 배포 검증)

## 7. React나 PHP로 만들 수 있나?

시스템이 3층으로 분리돼 있어 층마다 답이 다릅니다.

```
┌──────────────────────────────────────────────┐
│ 3층: UI (화면)          ← 거의 비어 있음        │  React 적합
├──────────────────────────────────────────────┤
│ 2층: 런타임 (검증·파이프라인)  ← Python 59개     │  PHP/Node 이식 가능
├──────────────────────────────────────────────┤
│ 1층: 스킬 (마크다운 매뉴얼)   ← .md 174개        │  언어 무관
└──────────────────────────────────────────────┘
```

**1층 (스킬)** — 텍스트 파일이므로 포팅 개념 자체가 없습니다.

**2층 (런타임)** — PHP로 충분히 가능합니다. 파이썬 코드가 하는 일은
frontmatter 파싱, JSON 스키마 검증, SHA-256 해시, 파일 입출력, 링크 검사, 락/롤백이며
**외부 라이브러리를 전혀 쓰지 않습니다**(표준 라이브러리만).

```php
hash_file('sha256', $path);              // 해시
json_decode(file_get_contents($p));      // 스키마
preg_match_all('/\[\[(.+?)\]\]/', ...);  // 위키링크
```

**3층 (UI)** — React가 적합하며, 현재 가장 비어 있는 영역입니다.
`dashboard.html`은 리다이렉트 한 줄, `tools/agentic_os_server.py`는 288줄 로컬 서버가 전부입니다.

### 단, 못 만드는 것

```
React/PHP로 되는 것:   파일 저장, 검사, 링크 확인, 화면 표시
React/PHP로 안 되는 것: 요약, 개념 추출, 판단          ← LLM만 가능
```

구조는 이렇게 됩니다.

```
[React 화면] ←→ [PHP API 서버] ←→ [파일: 옵시디언 볼트]
                     ↓
              [Claude API 호출]   ← 여기만 AI, 여기서 비용 발생
```

> 주의: 저장소 자체는 토큰이 불필요하지만, **웹앱으로 만들면 Claude API 키가 필요해집니다.**
> "Claude가 파일을 읽는" 구조에서 "웹앱이 Claude를 호출하는" 구조로 뒤집히기 때문입니다.

### 현실적인 1차 목표

**AI 없이 만들 수 있는 읽기 전용 대시보드부터.**

| 주차 | 작업 |
|---|---|
| 1주 | PHP로 볼트 폴더 스캔 → 노트 목록 JSON 출력 |
| 2주 | React로 목록 + 검색 화면 |
| 3주 | 위키링크 파싱 → 그래프 시각화 |
| 4주 | 건강도 체크 (깨진 링크, 출처 없는 노트) |

여기까지 **API 키 없이, 비용 0원으로** 가능합니다.

### A. AI 지식관리 템플릿 팩 판매

**무엇을** — 옵시디언 볼트 + 엄선한 스킬 + 한글 매뉴얼 + 설치 영상 + 7일 워크북

**왜** — 현재 최대 진입장벽이 "설치+설정"입니다. 남의 경로가 박혀 있고, 영어이고, 용어가 어렵습니다.
이 고통을 제거하는 것만으로 상품이 됩니다.

| 항목 | 값 |
|---|---|
| 가격 | 3.9만원(입문) / 9.9만원(프로 + 컨설팅 30분) |

### B. 버티컬 특화 구축 서비스 (마진 최고)

**무엇을** — 특정 업종 하나를 위한 AI 업무 시스템 구축 (컨설팅 + 세팅)

**왜 가능한가** — `ai-six-sigma-property-os` 스킬이 이미 완성형 원형입니다.

```
Define   → 고객 고통, 작업지시 유형, SLA, CTQ 정의
Measure  → 지표별 계산식·데이터출처·담당자·기준치 매핑
Analyze  → 병목·피시본·5Why로 원인 규명
Improve  → 가설·담당자·예산·성공지표·롤백조건이 붙은 개선 1개
Control  → 대시보드·알림·승인·예외·감사·리뷰주기
```

그리고 B2B 계약에서 결정적인 안전장치가 명시돼 있습니다.

> "고객 대상 견적, 가격/정책 변경, 저신뢰 배차, 안전, 규제, 개인정보, 결제,
> 케이스 종결, 징계는 **반드시 사람 승인 아래에 둔다**"

→ **"AI가 멋대로 하지 않습니다"를 문서로 증명 가능**합니다.

**타겟 업종 후보**

| 업종 | 첫 워크플로우 | 비고 |
|---|---|---|
| 부동산/시설관리 | 작업지시→배차→견적→증빙 | **스킬 원형 존재** |
| 세무/노무 사무소 | 상담기록→근거조항→문서초안 | 근거 추적이 핵심 |

| 병의원 | 논문→근거위키→환자설명자료 | 출처 필수 |

| 항목 | 값 |
|---|---|
| 가격 | 진단 200~500만원 / 구축 500~2000만원 / 유지 월 30~100만원 |

| 예상 수익 | 연 3~5건 = 연 3000만~1억 |

**리스크**
- 영업이 가장 어려움 → **첫 1건은 저가/무료로 레퍼런스 확보**
- "얼마나 아꼈나"를 못 대면 재계약 없음 → **시작 전 Before 수치 기록 필수** (CTQ/Measure 단계)

### D. 교육 상품 (콘텐츠가 이미 존재)

**킬러 주제**

> ### "AI가 '다 했어요'라고 거짓말 못 하게 만드는 법"

`verify-before-claim` 스킬 하나가 통째로 커리큘럼이 됩니다.

```
1강. AI는 왜 거짓말을 하는가 (노력 ≠ 성공)
2강. 주장을 "반증 가능한 한 문장"으로 바꾸기
3강. 위험도 3단계 분류 (낮음/중대/치명적)
4강. 가장 싼 검증 방법 고르기
5강. "신선한 증거" 원칙 — 왜 오래된 테스트는 무효인가
6강. 실전: 내 프로젝트에 검증 게이트 심기
7강. 트랜잭션 파이프라인 (Stage→Submit→Commit→Rollback)
8강. 영수증 시스템으로 에이전트 추적하기
```

| 형태 | 가격 | 제작 기간 | 예상 수익 |
|---|---|---|---|
| 전자책(PDF) | 1.5~3만원 | 3~4주 | 월 20~100만원 |
| 인프런 강의 | 5.5~11만원 | 2~3개월 | 월 30~500만원 (편차 큼) |
| 유료 뉴스레터 | 월 9,900원 | 지속 | 구독 200명 = 월 200만원 |

**리스크** — 인지도가 없으면 초반이 어려움 → 무료 콘텐츠(블로그 3~5편)로 반응 먼저 측정.
AI 분야는 6개월이면 내용이 낡음 → **도구가 아닌 원칙 중심**으로 작성.

**보너스** — 교육은 다른 아이디어의 **영업 채널**이 됩니다.
(강의 수강 → 템플릿 구매 → 컨설팅 문의로 이어지는 깔때기)

**평가** — 난이도 ★★☆☆☆ / 속도 ★★★★☆ / 수익 ★★★☆☆ / **추천도 ★★★★☆**

### E. AI 에이전트 감사(Audit) 서비스 (숨은 기회)

**무엇을** — "당신 회사가 도입한 AI, 제대로 일하고 있는지 감사해드립니다."

**왜 지금인가**
- 회사들이 AI를 일단 도입은 했음
- 그런데 "제대로 하고 있는지" 아무도 모름
- 사고 시 책임 소재가 불분명
- 경영진의 "효과 있나?" 질문에 답할 사람이 없음

**활용 스킬**

| 스킬 | 감사 항목 |
|---|---|
| `workflow-audit` | AI 업무 전수조사 → 자동화 가능/불가 판정 |
| `verify-before-claim` | "증거 없는 완료 선언" 사례 적발 |
| `harness-engineering` | 권한·관측성·복구 체계 점검 |
| `context-manager` | 토큰 낭비 진단 (비용 절감 = 경영진 관심사) |
| `agent-teams-command` | 멀티에이전트 권한 경계 점검 |

**산출물 (= 상품)**

```
AI 운영 진단 보고서
├── 위험 등급별 워크플로우 지도
├── "증거 없는 완료 선언" 적발 사례 N건
├── 사람 승인이 반드시 필요한 지점 목록
├── 토큰 비용 절감 포인트
└── 90일 개선 로드맵
```

| 항목 | 값 |
|---|---|
| 가격 | 진단 300~800만원 / 분기 재점검 월 50~150만원 |
| 제작 기간 | 체크리스트 3~4주 |
| 강점 | **경쟁자가 거의 없음** |

**리스크** — "감사"는 신뢰 장사이므로 권위가 먼저 필요 → **D(교육)와 세트로 진행**.
시장이 다소 이르지만 선점 효과 가능.

**평가** — 난이도 ★★★☆☆ / 속도 ★★★☆☆ / 수익 ★★★★☆ / **추천도 ★★★★☆**

### 추천 조합: D → A → E → B

하나만 고르지 말고, 서로를 먹여살리는 순서로 진행합니다.

```
D(교육/글쓰기)  ← 시작점. 신뢰·인지도 축적
     ↓ 독자 확보
A(템플릿 판매)  ← 그 독자에게 판매. 첫 현금 흐름
     ↓ "더 해달라"는 수요 발생
E(감사 서비스)  ← 고액 계약
     ↓ 사례 축적
B(버티컬 구축)  ← 최종 형태
```

**C(SaaS)는 A/E로 현금이 돌기 시작한 뒤에** 착수합니다.
